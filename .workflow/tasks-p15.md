### P15-002 统一订单编排服务

**目标**

建立唯一交易用例边界，使所有订单在同一处完成校验、风控、幂等、建单、冻结、报单和补偿。

**范围**

- 新增 `TradeApplicationService`。
- 新增 `POST /api/trade/orders`。
- 将旧 `/api/trade/order` 改为兼容入口，内部调用统一服务。
- 完成请求校验、幂等预检、状态机接入和审计埋点。
- 定义外部调用失败补偿接口。

**关键设计**

```
submit(CreateTradeCommand)
  -> validate
  -> authorize
  -> riskCheck
  -> prepareLocalOrderTransaction
  -> submitToGateway
  -> markSubmittedOrSubmitUnknown
  -> return TradeResult
```

**测试要求**

- 参数非法、无权限、风控拒绝、幂等重复、资金不足、网关拒单和网关超时。
- 10 并发相同幂等键。
- 旧接口不能绕过统一服务。

**准出**

- 请求通过统一入口完成全链路。
- 失败路径不留下未解释的冻结记录。

### P15-003 真实风控上下文与决策闭环

**目标**

让事前风控读取真实持仓、资金和下单历史，并使事中限制开仓规则在主链路生效。

**范围**

- 新增 `TradingRiskContextFactory`。
- 从 PG 读取账户、持仓和策略下单记录。
- 接入 `OpenBlockRegistry`。
- 风控异常默认拒绝。
- 风控结果写入 `risk_intercept_log`，关联 `orderId`。
- 与降级模块联动，只限制开仓，平仓放行。

**测试要求**

- 资金边界、持仓边界、频率边界。
- 风控规则抛异常。
- 开仓限制生效、平仓放行。
- 性能测试单次风控平均低于 1ms。

**准出**

- `DefaultRiskContext` 不再用于生产交易路径。
- 风控结果可追溯到订单请求。

### P15-004 资金冻结与结算闭环

**目标**

使资金变化与订单和成交严格对应，支持冻结、释放、保证金占用、手续费和已实现盈亏。

**范围**

- 新增 `FundReservationService`。
- 冻结记录以 `orderId` 唯一。
- 实现拒单、撤单和废单的释放。
- 实现成交后的保证金和手续费结算。
- 所有变化写入 `fund_flow`。
- 抽象 `MarginCalculator`，本期提供配置化简化实现。

**测试要求**

- 重复冻结、重复释放、重复手续费。
- 部分成交后撤单。
- 余额不足和并发冻结。
- 账户资金守恒。

**准出**

- 任意订单可查询冻结金额、已消耗金额和释放金额。
- 任意成交可追溯到资金流水。

### P15-005 网关回报流水线与幂等处理

**目标**

将网关订单和成交回报可靠地分发到 OMS、持仓和资金模块。

**范围**

- 启动时注册网关监听器。
- 新增 `GatewayReportDispatcher`。
- 回报先落 `gateway_report_log` 并去重。
- 按回报类型调用 OMS、持仓和资金服务。
- 处理乱序、重复、部分成交和失败重试。
- 回报处理与网关线程解耦，使用有界队列。

**测试要求**

- 重复回报 100 次。
- 乱序回报。
- 部分成交后成交回报。
- 处理失败后重试。
- 队列满时的拒绝策略。

**准出**

- 同一 `reportKey` 只产生一次业务效果。
- 回报失败可在日志和监控中查询。
