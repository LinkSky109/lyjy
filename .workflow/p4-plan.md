# P4 规划（单机自用的后续加固）

> 依据：`.workflow/delivery-report-p3.md` §6「后续建议」
> 定位：承接 P3 单机生产化，把已记录的后续项按价值/风险落地
> 延续约束：Java17/SpringBoot3.2.5/MyBatis-Plus/PG/CH/Kafka/Redis；本地优先；不拆微服务
> 明确不做（观察期项）：多活/灾备、微服务、K8s 集群、对外多租户

## 任务拆解

| 任务 | 名称 | 状态 | 验收要点 |
|------|------|------|----------|
| P4-001 | 行情分页翻页回补（更长历史） | ✅ DONE | 以最早 K 线为游标向前翻页；支持指定源；跨页去重可重复执行；单测 + 真实 E2E |
| P4-002 | bar_time 时区口径统一（巡检口径） | ✅ DONE | 巡检新鲜度用本地偏移比较，正常态 0h（消除 -8h 假滞后）；时区可配；不触碰存量数据 |
| P4-003 | 观测栈接入（本机 Prometheus/Grafana） | ✅ DONE | Prometheus 抓取 `/actuator/prometheus` 目标 up；Grafana 预置数据源+看板；脚本一键启停 |
| P4-004 | 备用行情源再增（更多公开源） | 候选 | 新增 MarketDataSource 实现即可，无需改核心 |

## 实施节奏
- 每任务一次「开发 → 测试 → 一致性」闭环（与 P0~P3 一致）。
- 完成后更新 `.workflow/context.yaml`（`p4_context`）与任务报告。

## 非目标（记录，不实施）
- 时区改动属跨切面（影响存量数据与回测口径），需独立评估窗口，不以进度换正确性。
