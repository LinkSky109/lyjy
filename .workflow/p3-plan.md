# P3 规划与任务拆解（单机生产化与可持续运营）

> 依据：`.workflow/delivery-report-p2.md` 后续建议 + 用户澄清「单人使用」
> 定位：把已在单人环境跑通的平台，加固为**可长期稳定自用**的单机生产系统
> 延续约束：Java17/SpringBoot3.2.5/MyBatis-Plus/PG/CH/Kafka/Redis；本地优先；不拆微服务

## 定位与非目标（重要）

**P3 做什么**：部署常驻、数据不丢、可观测、密钥更硬、性能与数据质量、可持续运营。
**P3 明确不做**（单人场景属于过度设计，记为观察期项）：
- 多活/异地灾备/机房级容灾
- 微服务拆分与服务网格
- 多租户对外商业化（多租户能力已具备，冻结不扩展）
- K8s 弹性伸缩（保留适配层，不落地集群）

## 模块清单（按依赖排序分批）

| 批次 | 模块 | 关键能力 |
|------|------|----------|
| A | 部署常驻与数据备份恢复 | 常驻托管（launchd/systemd）、PG+CH 备份、配置打包、恢复演练 |
| A | 日志与进程治理 | 日志轮转、进程守护与自愈、启动自检 |
| B | 可观测性 | Prometheus 指标端点、结构化日志、简单指标看板 |
| B | 密钥与安全加固 | KMS/HSM 真实接入、密钥轮换、访问审计强化 |
| C | 行情与数据质量 | 历史行情分页回补、bar 数据质量校验、缺口检测 |
| C | 性能与容量 | 回测/优化性能、连接池与超时调优、容量水位基线 |

## 观察期项（记录，不实施）
- 多活/灾备/同城双活；微服务拆分；K8s 集群与 HPA 实装；对外多租户运营。

## 实施节奏
- 每任务一次「开发 → 测试 → 一致性」闭环（与 P0/P1/P2 一致）；优先 P3-001（数据可靠性最基础）。
- 完成后更新 `.workflow/context.yaml`（`p3_context`）与任务报告。
