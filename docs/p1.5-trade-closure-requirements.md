# P1.5 交易主链路闭环与工程化加固需求规格

**文档版本**: v1.0
**编制日期**: 2026-10-05
**上游基线**: P0 本地交付基线 + P1 第一批已完成代码
**目标阶段**: P1.5
**状态**: 待确认
**关联工作流**: TASK-20261005-002

> 本阶段不新增业务模块，目标是让现有模块从“接口各自可用”升级为“交易主链路真实闭环”，并补齐继续推进 P1 第二批所必需的数据、权限、环境和测试基础。

## 1. 背景与问题定义

### 1.1 当前事实

| 编号 | 问题 | 代码证据 | 业务影响 |
|------|------|----------|----------|
| I-01 | 下单入口绕过事前风控 | `TradeController.placeOrder` 直接调用 `TradeExecutionService.placeOrder` | 风控可被绕过，不能保证所有订单先风控 |
| I-02 | 风控上下文是固定模拟值 | `RiskController.DefaultRiskContext` 返回固定资金和零持仓 | 风控结论不代表真实账户，可能误放行或误拦截 |
| I-03 | OMS 与柜台报单未联动 | `OrderManagementController` 只提供独立 CRUD，网关没有注册 OMS 回报监听器 | 订单状态可能长期停留在本地状态，无法追踪柜台生命周期 |
| I-04 | 资金服务与成交未联动 | `freezeCash/releaseCash/chargeCommission` 没有交易链路调用方 | 报单后不冻结资金，成交后 PG 账面与柜台账户分离 |
| I-05 | 持仓和成交只存在内存 | `MockCTPGateway` 使用 `Map/List` 保存订单、成交和持仓 | 服务重启后交易状态丢失，无法审计和恢复 |
| I-06 | 网关回报没有消费闭环 | `TradingGateway` 定义了监听器，但没有业务监听器注册 | 成交回报不会更新 OMS、持仓和资金 |
| I-07 | LIVE 模式静默回退 Mock | `TradeExecutionService.connect` 在 LIVE 模式只打印警告后仍使用 Mock | 生产环境可能误以为已连接真实柜台 |
| I-08 | Python 实盘 API 是占位实现 | `LiveDataAPI.get_position/get_account` 返回空，`LiveOrderAPI` 返回伪造订单号 | 用户策略无法通过 SDK 完成实盘下单、查单和撤单 |
| I-09 | 权限矩阵未实现 | 只有可自助领取的 `X-Confirm-Token`，没有角色拦截和范围过滤 | 敏感操作缺少真正的授权边界，不符合 P1 PRD |
| I-10 | 本地环境不能一键初始化完整 schema | Compose 只挂载 `init-db.sql`，P1、数据治理和 ClickHouse 脚本未自动执行 | 新环境启动后部分功能会因缺表而失败 |
| I-11 | 质量门槛没有真正执行 | Python 覆盖率 65%，CI 未设置 `--cov-fail-under`；Java 没有覆盖率插件和集成测试 | 回归缺陷只能在人工联调时发现 |
| I-12 | 工作流文档落后于代码 | 文档记录 81 文件/47 端点/3 个 P1 任务，实际已是 112 主源码/78 端点，P1-004 已有实现 | 后续排期和准出判断失真 |

### 1.2 根因

现有实现以“功能接口”为单位建设，缺少一个跨模块的应用编排层。风控、OMS、资金、网关、持仓和回报处理分别可用，但没有统一的交易用例边界、事务边界、补偿策略和幂等机制。

### 1.3 阶段定位

| 阶段 | 内容 | 与本阶段关系 |
|------|------|--------------|
| P0 | 行情、回测、Mock 交易、OMS、事前风控、基础资金 | 提供可复用模块和表结构 |
| P1 第一批 | 监控、事中风控、异常交易、降级 | 本阶段需要接回主链路 |
| P1.5 | 下单主链路闭环、持久化、权限、环境、测试门槛 | 本阶段 |
| P1 第二批/第三批 | 多柜台、日终清算、组合、VaR、策略安全 | 本阶段完成后继续 |
| P2 | 真实 CTP、微秒链路、多租户、监管报送、灾备 | 不在本阶段实现真实 CTP |

## 2. 目标与成功标准

### 2.1 总体目标

建立唯一且不可绕过的交易主链路：

```
策略/API 下单
  -> 身份与参数校验
  -> 真实事前风控
  -> 幂等建单
  -> 资金冻结
  -> 柜台报单
  -> 订单/成交回报
  -> OMS 状态、持仓、资金同步
  -> 审计与对账可追溯
```

### 2.2 量化目标

| 编号 | 目标 | 验收口径 |
|------|------|----------|
| G-01 | 所有策略订单必须经过统一入口 | 代码中不存在绕过编排层直接报单的生产路径 |
| G-02 | 风控使用真实数据 | 持仓、可用资金、总资产、下单频率均来自 PG 或柜台适配层 |
| G-03 | 订单、成交、持仓可恢复 | 服务重启后 PG 中数据完整，Mock 网关重连后可对账 |
| G-04 | 资金变化可追溯 | 每笔冻结、释放、手续费、盈亏都能关联到 `orderId/tradeId` |
| G-05 | 回报处理幂等 | 同一订单回报和成交回报重复投递不产生重复更新 |
| G-06 | 下单链路可观测 | 每个请求具备 `traceId`，关键节点有结构化日志和指标 |
| G-07 | 本地环境一键可用 | 全新环境执行文档步骤后可自动创建 PG/CH 所需表 |
| G-08 | 质量门槛可阻断 | Java 和 Python 覆盖率均不低于 80%，集成测试失败即阻断 |
| G-09 | Python 实盘 API 可用 | Mock 环境下可完成下单、查询、撤单、持仓和账户查询 |
| G-10 | 权限按角色生效 | 未授权角色无法执行写操作，查询范围按角色过滤 |

### 2.3 非目标

- 不实现真实 CTP 原生 SDK 对接，只保留稳定接口和 LIVE 失败快路径。
- 不实现多柜台路由和自动故障切换，该工作仍属 P1-005。
- 不实现日终清算批次、组合管理、VaR、策略加密和沙箱。
- 不引入微服务拆分、事件总线替换或新的重型中间件。
- 不实现多租户、AML、监管报送和异地灾备。

## 3. 用户与核心场景

### 3.1 用户角色

| 角色 | 核心诉求 | 关键权限 |
|------|----------|----------|
| TRADER | 通过 SDK 或 API 下单、撤单、查询自己的订单和持仓 | 仅本人策略数据 |
| RISK_OFFICER | 查看和配置风控，确认强制平仓 | 全量风控读写，敏感操作二次确认 |
| FUND_MANAGER | 查看资金流水、处理对账差异 | 资金和清算数据读写 |
| ADMIN | 配置、降级、环境维护 | 全量管理，但不能绕过风控执行普通订单 |
| COMPLIANCE | 审计订单、回报、风控和资金链路 | 全量只读，审计日志读写 |
| VIEWER | 只读查看监控和报表 | 全量只读，不允许写操作 |

### 3.2 核心用例

| 编号 | 用例 | 结果 |
|------|------|------|
| UC-01 | 策略提交限价开仓单 | 风控通过、冻结保证金、报单成功、订单可查询 |
| UC-02 | 策略提交被风控拒绝的订单 | 不创建可报单，返回明确原因并记录拦截日志 |
| UC-03 | 客户端重复提交相同下单请求 | 返回原订单，不重复冻结、不重复报单 |
| UC-04 | 相同幂等键提交不同内容 | 返回 409，不改变原订单 |
| UC-05 | 市价平仓成交 | OMS 更新成交，持仓减少，保证金释放，手续费入流水 |
| UC-06 | 撤单成功 | 未成交冻结资金释放，订单状态变为 CANCELED |
| UC-07 | 重复收到同一成交回报 | 只处理一次，持仓和资金不重复变化 |
| UC-08 | 服务重启 | 从 PG 恢复订单、成交、持仓、资金，和网关可对账 |
| UC-09 | LIVE 模式启动但真实适配器未实现 | 启动失败并返回明确原因，不静默回退 Mock |
| UC-10 | 未授权用户尝试降级或强平 | 返回 403 或 409，操作不生效并留审计记录 |

## 4. 业务规则与端到端流程

### 4.1 正常下单流程

1. 校验身份、角色、账户归属和数据范围。
2. 校验必填字段、枚举、价格、数量和精度。
3. 通过 `ClientOrderId` 或 API 幂等键执行幂等预检。
4. 构建真实 `RiskContext`，执行事前风控、开仓限制和过载保护。
5. 在本地事务中创建 OMS 订单、幂等记录和资金冻结记录。
6. 提交柜台报单，记录 `exchangeOrderId`。
7. 柜台回报到达后，由回报流水线更新订单、成交、持仓和资金。
8. 记录审计事件、结构化日志和指标。

### 4.2 事务与补偿规则

| 步骤 | 事务策略 |
|------|----------|
| 幂等记录 + OMS 订单 + 资金冻结 | 同一 PG 本地事务 |
| 调用外部柜台 | 本地事务提交后执行，不持有数据库长事务 |
| 柜台拒单 | 补偿解冻资金，订单转 REJECTED |
| 柜台超时且结果未知 | 订单转 SUBMIT_UNKNOWN，进入查询和对账队列 |
| 回报处理 | 每个回报独立事务，先去重再更新业务表 |
| 重复回报 | 直接返回已处理结果，不重复记账 |

### 4.3 成交处理规则

1. 按 `tradeId` 去重。
2. 校验成交对应的 OMS 订单存在且账户、策略、标的一致。
3. 更新订单累计成交量和均价。
4. 开仓成交：冻结资金转为保证金占用，扣手续费。
5. 平仓成交：按持仓成本和成交价计算已实现盈亏，释放对应保证金，扣手续费。
6. 更新持仓数量和成本；禁止持仓变为负数。
7. 写入成交记录和资金流水，并发布监控指标。

### 4.4 撤单流程

1. 校验订单归属和当前状态允许撤单。
2. 发送撤单请求。
3. 收到 CANCELED 回报后，释放未成交部分对应的冻结资金。
4. 已部分成交部分不得释放。
5. 重复撤单请求返回幂等结果。

### 4.5 重启与恢复流程

1. 启动时加载 PG 中的活跃订单。
2. 向网关查询订单和成交。
3. 对缺失回报进行补偿处理。
4. 以 PG 为系统账，以网关为对手账执行资金和持仓对账。
5. 差异生成对账记录并标记 `MISMATCHED`。

### 4.6 不可变业务不变量

| 编号 | 不变量 |
|------|--------|
| INV-01 | 任何普通订单都不能绕过统一编排层直接到达网关 |
| INV-02 | 风控拒绝的订单不产生资金冻结和柜台报单 |
| INV-03 | 同一幂等键最多对应一个 OMS 订单 |
| INV-04 | 同一 `tradeId` 最多影响一次持仓和资金 |
| INV-05 | 冻结总额不大于账户可用资金 |
| INV-06 | 持仓数量、可用数量不得小于零 |
| INV-07 | 资金流水金额之和必须能解释账户余额变化 |
| INV-08 | 所有成交必须能追溯到订单、账户和策略 |
| INV-09 | LIVE 模式下不得使用 Mock 网关 |
| INV-10 | 敏感操作必须同时通过角色校验和二次确认 |

## 5. 功能需求

### FR-01 统一订单入口

**优先级**: 必须

- 新增统一入口 `POST /api/trade/orders`。
- 入参必须包含 `accountId`、`strategyId`、`symbol`、`direction`、`offsetFlag`、`orderType`、`quantity`、`idempotencyKey`。
- 限价单必须提供 `price`，市价单允许不传价格。
- 旧 `/api/trade/order` 标记为 deprecated，只允许内部兼容调用，不能直接访问网关。

**验收标准**

- 通过旧入口无法绕过编排层。
- OpenAPI 或接口文档中标注新旧入口关系和弃用时间。

### FR-02 请求校验

**优先级**: 必须

- 对方向、开平、订单类型、正数和精度执行校验。
- 对账户、策略、标的归属执行校验。
- 市价单在无参考价时必须使用显式策略或拒绝，不能由网关随意兜底。

**验收标准**

- 非法请求返回 400 和字段级错误。
- 不产生 OMS 记录、冻结记录或网关调用。

### FR-03 真实事前风控

**优先级**: 必须

- 使用 PG 持仓、资金和 OMS 下单历史构建 `RiskContext`。
- 事中限制开仓清单必须参与校验。
- 平仓订单默认放行风控，但必须经过持仓可平数量校验。
- 风控规则异常默认拒绝，不允许静默放行。

**验收标准**

- 替换 `DefaultRiskContext` 后，仓位、资金和频率规则使用真实数据。
- 风控拦截日志包含 `orderId`、规则码、原因和请求快照。

### FR-04 幂等建单

**优先级**: 必须

- `idempotencyKey` 唯一。
- 相同 key 和相同请求摘要返回原订单。
- 相同 key 和不同摘要返回 409。
- 并发请求同一 key 时，只能有一个创建成功，其他请求返回同一结果或冲突。

**验收标准**

- 并发 10 次相同请求只产生 1 个订单和 1 次冻结。

### FR-05 OMS 生命周期

**优先级**: 必须

- 订单状态至少覆盖 PENDING、SUBMITTED、ACCEPTED、PARTIAL_FILLED、FILLED、CANCELED、REJECTED、SUBMIT_UNKNOWN。
- 所有状态流转必须经过状态机。
- 订单记录必须包含 `offsetFlag`、`exchangeOrderId`、成交数量、成交均价和错误码。

**验收标准**

- 非法状态流转被拒绝并记录告警。
- 任意订单可通过 `orderId` 查询完整生命周期。

### FR-06 资金冻结与释放

**优先级**: 必须

- 开仓前冻结预计保证金和预计手续费。
- 冻结操作以 `orderId` 为业务唯一键。
- 拒单、撤单和废单释放未成交部分。
- 成交后按成交记录进行保证金和手续费结算。
- 释放和扣减必须防止重复执行。

**验收标准**

- 任意时刻 `available + frozen + margin` 与总资产关系可解释。
- 重启和重复回报不会重复冻结或重复释放。

### FR-07 柜台报单边界

**优先级**: 必须

- 编排层负责准备订单、冻结资金和记录审计后调用网关。
- 网关接口不得依赖 Controller 或 MyBatis 实体。
- 报单失败必须执行补偿。

**验收标准**

- 网关实现可替换为 Mock 或真实适配器。
- 外部调用失败不会遗留本地事务锁。

### FR-08 回报流水线

**优先级**: 必须

- 网关启动后注册订单和成交监听器。
- 回报先标准化、再幂等去重、再分发到 OMS、持仓和资金服务。
- 订单回报和成交回报可乱序到达，必须按状态机与累计成交规则处理。

**验收标准**

- 重复、乱序和部分成交流程测试通过。
- 回报处理失败可重试，并保留失败原因。

### FR-09 成交与持仓持久化

**优先级**: 必须

- 新增成交记录实体和 Mapper。
- 增加 `position` 实体和 Mapper。
- 持仓按 `accountId + strategyId + symbol + direction` 维护。
- 支持开仓成本加权、平仓扣减和可用数量更新。

**验收标准**

- 服务重启后持仓可查询。
- 同一成交重复处理后持仓数量不变。

### FR-10 资金与持仓对账

**优先级**: 必须

- 对账输入为 PG 系统账和网关查询结果。
- 比较总资产、可用资金、保证金和持仓数量。
- 差异记录必须包含账户、标的、系统值、柜台值、差异和原因。

**验收标准**

- 正常流程对账为 MATCHED。
- 人为制造差异时可生成 MISMATCHED 记录。

### FR-11 运行模式治理

**优先级**: 必须

- 明确支持 `MOCK`、`LIVE` 和后续扩展模式。
- LIVE 适配器未实现时，启动或连接必须直接失败。
- API、SDK 和健康检查必须暴露当前模式。

**验收标准**

- LIVE 模式不会连接到 Mock。
- 错误信息明确指出缺失的真实适配能力。

### FR-12 Python 实盘 SDK

**优先级**: 必须

- 实现真实 REST 下单、查单、撤单、成交、持仓和账户查询。
- 自动携带 `idempotencyKey`、`X-User-Id`、`X-User-Role`。
- 支持超时、重试、错误码解析和结构化异常。
- 实盘 API 不允许在未连接或无权限时返回伪造成功。

**验收标准**

- SDK 集成测试可连接 Mock 核心服务完成完整交易用例。

### FR-13 权限与审计

**优先级**: 必须

- 新增认证拦截器和角色校验切面。
- 写接口按角色授权，TRADER 只能访问本人策略和订单。
- 敏感操作需要有效确认令牌，确认令牌签发也必须经过授权。
- 关键操作写入审计日志。

**验收标准**

- 每个角色的允许和拒绝用例通过。
- 越权请求不改变任何业务数据。

### FR-14 可观测性

**优先级**: 必须

- 每个请求生成或透传 `traceId`。
- 日志覆盖请求、风控、建单、冻结、报单、回报、成交、资金和持有关键节点。
- 指标至少包含下单耗时、拒单率、报单失败率、回报延迟、成交笔数、资金冻结失败和对账差异。

**验收标准**

- 给定 `orderId` 可检索完整链路日志。
- 指标可在监控接口查询。

### FR-15 降级与过载保护联动

**优先级**: 必须

- 过载保护只限制开仓，平仓和减仓必须放行。
- 网关和存储调用接入熔断状态上报。
- 降级不能绕过风控、幂等和资金冻结。

**验收标准**

- 过载时新开仓拒绝、平仓成功。
- 降级状态变化可在审计日志和监控中查询。

### FR-16 本地环境初始化

**优先级**: 必须

### 6.3 订单状态机

```
PENDING
  -> SUBMITTED
  -> ACCEPTED
  -> PARTIAL_FILLED
  -> FILLED

PENDING -> REJECTED
SUBMITTED/ACCEPTED/PARTIAL_FILLED -> CANCELED
SUBMITTED -> SUBMIT_UNKNOWN -> ACCEPTED/REJECTED/CANCELED
```

规则：

- 终态为 FILLED、CANCELED、REJECTED。
- SUBMIT_UNKNOWN 必须通过查询或对账收敛。
- 回报乱序时以累计成交量和终态优先级判定。

### 6.4 资金记账约定

- 冻结资金减少 `available_cash`，增加 `frozen_cash`。
- 成交后保证金从 `frozen_cash` 转入 `margin`。
- 手续费从 `available_cash` 扣减并写 `COMMISSION` 流水。
- 平仓释放保证金并结算已实现盈亏。
- 每笔流水必须记录 `biz_type` 和 `biz_no`，`biz_no` 尽量使用 `orderId` 或 `tradeId`。

## 7. 接口需求

### 7.1 新增统一交易接口

#### POST /api/trade/orders

请求示例：

```json
{
  "accountId": "DEFAULT-001",
  "strategyId": "S-001",
  "symbol": "rb2410",
  "exchange": "SHFE",
  "direction": "BUY",
  "offsetFlag": "OPEN",
  "orderType": "LIMIT",
  "price": 3500,
  "quantity": 2,
  "idempotencyKey": "S-001-20261005-0001"
}
```

成功响应：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "orderId": "ORD-...",
    "status": "SUBMITTED",
    "exchangeOrderId": "EX...",
    "traceId": "..."
  }
}
```

错误码：

| HTTP | 业务码 | 含义 |
|------|--------|------|
| 400 | `VALIDATION_FAILED` | 参数非法 |
| 403 | `FORBIDDEN` | 无权限 |
| 409 | `IDEMPOTENCY_CONFLICT` | 幂等键冲突 |
| 422 | `RISK_REJECTED` | 风控拒绝 |
| 422 | `INSUFFICIENT_FUNDS` | 资金不足 |
| 503 | `GATEWAY_UNAVAILABLE` | 柜台不可用 |

#### GET /api/trade/orders/{orderId}

返回 OMS 订单、最近成交、资金冻结和回报处理状态。

#### DELETE /api/trade/orders/{orderId}

按业务订单号撤单，不接受直接使用 `exchangeOrderId` 作为主入口。

#### GET /api/trade/positions

返回 PG 持仓，支持按账户、策略和标的过滤。

#### GET /api/trade/account

返回 PG 账户、冻结、保证金和最近资金流水摘要。

### 7.2 兼容策略

- 旧接口保留一个迭代，返回弃用警告和 `Sunset` 头。
- 旧接口内部改为调用统一编排层。
- 禁止保留直接访问网关的 Controller 方法。

## 8. 非功能需求

### 8.1 性能

- 本地 Mock 环境统一下单接口 P99 不高于 50ms。
- 事前风控平均耗时低于 1ms，不含外部 I/O。
- 本地过载保护基线保持 500 TPS。
- 回报处理不得阻塞网关回调线程，使用有界队列。

### 8.2 一致性

- 本地事务保证幂等、订单和冻结记录原子性。
- 外部调用采用“本地事务 + 补偿”模式。
- 回报处理采用幂等消费。
- 对账是最终一致性的兜底手段。

### 8.3 安全

- 所有写操作必须校验角色和数据范围。
- 敏感操作使用一次性确认令牌。
- 仓库不保存生产凭据，本地密码使用环境变量。
- 日志不得记录密码、令牌和完整账户敏感信息。

### 8.4 可观测性

- 结构化日志字段至少包含 `traceId`、`orderId`、`accountId`、`strategyId`、`symbol`。
- 关键指标进入现有监控模块。
- 回报失败和补偿失败产生告警事件。

### 8.5 兼容性

- Java 17、Spring Boot 3.2、MyBatis-Plus 3.5 保持不变。
- 数据库变更必须可增量执行。
- Python SDK 保留现有回测 API。

### 8.6 可运维性

- 支持健康检查、运行模式查询和 schema 版本检查。
- 提供一键初始化脚本和本地验收脚本。
- 失败状态可查询、可重试、可对账。
