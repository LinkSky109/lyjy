# 功能优化设计（v1.1）

日期：2026-10-23
范围：`web/` 管理端、`core/` 只读聚合与交易/资金/风控接口
原则：不破坏现有接口；先补工作流，再补可视化；所有数字来自后端，不在前端编造。

## 1. 现状诊断

当前 16 条路由按“能力域”组织，功能覆盖完整，但存在四个断点：

| 断点 | 现状 | 影响 |
|---|---|---|
| 首页只汇总不决策 | 有状态条、指标、告警、持仓、在途委托，但没有待办与今日盈亏 | 用户仍需逐页寻找“现在该处理什么” |
| 交易页效率不足 | 合约手输、无批量撤单、成交不分页、无键盘操作 | 高频交易路径长，易输错 |
| 风控不可运营 | 规则可开关，阈值只读 | 参数调整必须改配置重启 |
| 资金/组合缺闭环 | 出入金有审核，但无账户互转；审批无时间线 | 多账户资金调拨靠线下 |

## 2. 目标信息架构

保留现有路由，侧栏按“工作流”重排，减少跨组跳转：

```
总览        仪表盘
交易        交易工作台、资金管理、组合管理
风险        事前风控、事中风控、VaR、异常交易
运营        日终清算、监控告警、多柜台网关
策略与治理  策略安全、回测、风控看板、性能降级
```

角色化默认落点：

- 交易员 → `/trading`
- 风控 → `/risk`
- 运营 → `/fund`
- 管理员 → `/dashboard`

## 3. 工作流一：交易工作台（A）

### 3.1 目标

把“查行情 → 选合约 → 下单 → 撤单 → 看成交”收敛到一屏，减少手输与误操作。

### 3.2 接口

| 接口 | 说明 |
|---|---|
| `GET /api/trade/instruments?exchange=&keyword=` | 合约搜索，返回现有 `InstrumentView` 列表 |
| `GET /api/trade/trades?accountId=&symbol=&from=&to=&page=&size=` | 成交分页；不传 `page` 保持旧数组契约 |
| `POST /api/trade/orders/batch-cancel` | body `{ orderIds: string[], reason?: string }`，逐单返回 `{ orderId, success, status?, message? }` |

### 3.3 前端交互

1. 合约输入改为 `input + datalist`，支持代码/名称模糊搜索，保留手输回退。
2. 下单预检：价格档位、数量步进、涨跌停、交易状态、名义价值、预计保证金、下单后可用资金。
3. 批量撤单：仅对当前页 `cancelable=true` 的委托生效，二次确认，逐单结果提示。
4. 成交页签分页，默认 20 条。
5. 键盘：`/` 聚焦合约，`Alt+B` / `Alt+S` 切换买卖，`Ctrl/Cmd+Enter` 打开确认，`Esc` 关闭弹窗。
6. 订单详情增加状态时间线：创建 → 已提交 → 成交/撤销/拒绝。

### 3.4 验收

- 合约搜索选中后自动带出交易所与盘口。
- 数量/价格不满足合约规则时，提交按钮前置校验直接拦截。
- 批量撤单部分成功时，成功与失败逐单可见。
- 成交分页与订单分页使用同一套分页组件与文案。

## 4. 工作流二：决策首页（B）

### 4.1 目标

首屏回答三个问题：系统是否正常、今天赚亏多少、现在有什么要处理。

### 4.2 接口

`GET /api/dashboard/summary` 增量字段（只增不改）：

```json
{
  "pnl": {
    "todayRealized": -120.5,
    "todayCommission": 18.2,
    "todayCombined": -138.7,
    "todayTrades": 6
  },
  "todos": {
    "pendingCash": 2,
    "openAlerts": 3,
    "criticalAlerts": 1,
    "cancelableOrders": 4
  }
}
```

`GET /api/dashboard/timeline?limit=20`：

```json
{
  "items": [
    { "type": "ORDER|TRADE|ALERT", "id": "...", "title": "...", "status": "...", "severity": "...", "amount": 0, "at": "2026-10-23T10:00:00" }
  ]
}
```

### 4.3 前端

- 指标区增加“今日已实现盈亏”“今日手续费”“今日成交笔数”。
- 新增“待办中心”卡片：待审出入金、未确认告警、严重告警、可撤委托，点击直达对应页面并带筛选参数。
- 新增“最近动态”时间线，混合委托、成交、告警，最多 20 条。
- 保持现有状态条、账户与风险、在途委托。

### 4.4 验收

- 首屏只调用 `summary` 即可渲染指标与待办；时间线独立失败不影响首屏。
- 待办数字与对应页面筛选结果一致。
- 无数据时显示空状态，不显示 0 元伪造曲线。

## 5. 工作流三：风控运营（C）

### 5.1 目标

规则参数可在线调整、立即生效、可追溯；预算接近上限时提前提示。

### 5.2 接口

| 接口 | 说明 |
|---|---|
| `PUT /api/risk/rules/{ruleCode}` | body `{ thresholdParams, action, operator }`；校验 JSON 与规则支持的键 |
| `GET /api/risk/rules` | 已有，补充 `defaultThresholdParams` 与 `editable` |

支持动态参数的规则：

| ruleCode | 参数 |
|---|---|
| `POSITION_LIMIT` | `maxVolume`、`maxRatio` |
| `FUND_CHECK` | `marginRatio`、`minCashRatio` |
| `FREQ_LIMIT` | `maxPerSecond`、`maxPerMinute` |

`BLACKLIST`、`SELF_TRADE` 无数值阈值，保持只读。

### 5.3 前端

- 规则表增加“阈值”编辑弹窗，按规则渲染字段与单位，保存后 Toast 并刷新。
- 展示参数来源（默认/配置覆盖）与最近更新时间。
- 风险预算表增加占用率进度条：`<80%` 正常、`80–99%` 警告、`>=100%` 拦截。
- 规则保存失败时就近展示后端校验原因。

### 5.4 验收

- 修改阈值后，下一次下单试算立即使用新值，无需重启。
- 非法 JSON、未知参数、越界值返回 400 且前端可见。
- 预算占用率与 `usageRate` 一致，颜色不只作为唯一信息通道。

## 6. 工作流四：资金与组合（D）

### 6.1 目标

多账户资金可调拨、审批过程可追溯；再平衡从“填 JSON”变为向导。

### 6.2 接口

| 接口 | 说明 |
|---|---|
| `POST /api/fund/transfer` | `{ fromAccountId, toAccountId, amount, currency, idempotencyKey, operator }`；服务端校验可用资金/币种/账户状态，写双边流水 |
| `GET /api/fund/transactions?status=&page=&size=` | 出入金/划转审批列表与时间线 |
| `GET /api/fund/transfer/{transferNo}` | 划转详情与双边流水号 |

新增表 `fund_transfer`：`transfer_no`、`from_account_id`、`to_account_id`、`amount`、`currency`、`status`、`idempotency_key`、`operator`、`create_time`、`complete_time`。

### 6.3 前端

- 资金页新增“账户互转”页签：转出/转入账户、金额、币种、幂等键，提交前展示转出后余额。
- 审批区增加状态时间线：申请 → 审核 → 完成/拒绝。
- 组合再平衡改为三步向导：选择组合与目标 → 预览差异 → 确认执行；原始 JSON 保留在高级选项。
- 组合详情增加基准对比占位（无数据时不画线）。

### 6.4 验收

- 转账前后两个账户余额与双边流水一致，重复幂等键不重复扣款。
- 出金/划转均不能使可用资金为负。
- 再平衡确认前必须看到预览差异；确认后展示任务状态。

## 7. 分期与依赖

| 阶段 | 内容 | 依赖 | 风险 |
|---|---|---|---|
| E | 本文档 | 无 | 低 |
| A | 合约搜索、成交分页、批量撤单、下单预检、快捷键 | 现有行情/合约/OMS | 中 |
| B | 今日盈亏、待办、时间线 | 订单/成交/告警/出入金表 | 低 |
| C | 阈值动态注入、预算预警 | 规则实现改造 | 中 |
| D | 账户互转、审批时间线、再平衡向导 | 新表 + 迁移 | 中高 |

## 8. 兼容与回滚

- 所有新增字段只增不改；旧前端忽略新字段。
- `GET /api/trade/trades` 不传 `page` 时保持数组返回。
- 风控阈值保存失败不落库；规则实例保留上一份有效参数。
- 资金划转使用本地事务；失败整体回滚，不留单边流水。
- 新增接口均可通过路由级回退：前端 404 时展示空状态而非白屏。

## 9. 不在本期范围

- WebSocket/SSE 实时推送（继续轮询）
- 微服务拆分、BFF 层
- 多币种自动换汇
- 跨租户资金调拨
