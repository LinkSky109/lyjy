> 测试状态: 待执行

---

## 1. 测试目标

验证以下核心承诺：

1. 所有订单必须经过统一入口、真实风控、幂等建单、资金冻结和柜台报单。
2. 重复、乱序和部分成交回报不会造成重复记账或状态错乱。
3. 服务重启后，订单、成交、持仓和资金可以从 PG 恢复并对账。
4. LIVE 模式不会静默回退 Mock。
5. Python SDK 可以完成 Mock 环境下单、查询、撤单、持仓和账户查询。
6. 权限、安全和质量门槛可阻断不合规变更。

## 7. 端到端测试

### E2E-001 正常开平仓

```
Python SDK 开仓
  -> 统一入口
  -> 真实风控通过
  -> 创建 OMS 订单
  -> 冻结保证金和手续费
  -> Mock 网关成交
  -> 成交回报处理
  -> 持仓增加
  -> Python SDK 平仓
  -> 持仓减少
  -> 保证金释放
  -> 对账 MATCHED
```

### E2E-002 风控拒绝

```
Python SDK 下单
  -> 风控拒绝
  -> OMS 记录 REJECTED
  -> 无冻结、无报单
  -> SDK 收到结构化错误
```

### E2E-003 幂等重试

```
SDK 相同 idempotencyKey 重试 3 次
  -> 只产生一个订单
  -> 只冻结一次
  -> 三次返回同一 orderId
```

### E2E-004 重启恢复

```
下单并成交
  -> 重启核心服务
  -> 查询订单、成交、持仓、资金
  -> 与 Mock 网关对账
  -> 数据一致
```

### E2E-005 权限边界

```
TRADER-001 登录
  -> 查询本人订单成功
  -> 查询 TRADER-002 订单失败
  -> 调用降级开关失败
  -> 尝试强平失败
```

## 8. 性能测试

| 指标 | 目标 | 测试方法 |
|------|------|----------|
| 统一下单 P99 | ≤ 50ms | 本地 Mock，稳定并发 |
| 风控平均耗时 | < 1ms | 预热后样本统计 |
| 订单入口容量 | 500 TPS 基线 | 令牌桶和压测 |
| 回报处理吞吐 | 不低于订单 TPS | 有界队列压测 |
| 重复回报处理 | 不产生重复记账 | 100 倍重复投递 |

性能测试失败不自动判定为功能缺陷，但必须形成容量报告并由人工决定是否阻断发布。

## 10. 缺陷等级

| 等级 | 判定 | 处理 |
|------|------|------|
| 阻断 | 数据丢失、重复报单、重复记账、安全问题 | 停止测试，立即回退开发 |
| 严重 | 主链路不可用、状态无法收敛、权限失效 | 本阶段必须闭环 |
| 一般 | 边界功能错误、监控缺失 | 本阶段闭环 |
| 轻微 | 文案、非关键展示 | 可记录到后续，但需人工确认 |
